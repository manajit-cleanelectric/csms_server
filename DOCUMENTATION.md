# CSMS Server - Complete Documentation Guide

## Overview

This document provides comprehensive documentation for all files in the `src/` folder of the Charging Station Management System (CSMS) server. The documentation is generated using TypeDoc from JSDoc comments in the source code.

## Generated Documentation

The main documentation is available in HTML format in the `docs/` folder, generated by TypeDoc. This includes:

- **API Documentation** - All functions, classes, and interfaces
- **Module Structure** - Complete file organization  
- **Type Definitions** - TypeScript interfaces and types
- **Cross-references** - Links between related components

## How to View Documentation

### Option 1: Local File System
Open `docs/index.html` in your web browser to view the documentation locally.

### Option 2: Local Server
Run the following command to serve documentation with live reload:
```bash
npm run docs:serve
```
This will:
1. Regenerate the documentation
2. Start a local server on http://localhost:8080
3. Automatically open the documentation in your browser

## How to Regenerate Documentation

### Automatic Generation
```bash
npm run docs
```

### Manual TypeDoc Command
```bash
npx typedoc
```

### Configuration
Documentation generation is configured in `typedoc.json`:
- **Entry Points**: All files in `src/` folder
- **Output**: `docs/` folder
- **Theme**: Default TypeDoc theme
- **Options**: Includes private/protected members, excludes externals

## Documentation Best Practices

### JSDoc Comments
The codebase uses comprehensive JSDoc comments that TypeDoc converts to documentation:

```typescript
/**
 * Description of the function
 * @param {type} paramName - Parameter description
 * @returns {type} Return value description
 * @throws {ErrorType} When this error occurs
 * @example
 * // Usage example
 * functionName(param);
 */
```

### Supported JSDoc Tags
- `@param` - Parameter documentation
- `@returns` - Return value documentation
- `@throws` - Exception documentation
- `@example` - Usage examples
- `@deprecated` - Deprecated functionality
- `@since` - Version information
- `@see` - Cross-references

### Custom Tags (Warnings)
Some custom tags generate warnings but don't break documentation:
- `@async` - Use standard async/await documentation instead
- `@constant` - Use `@const` or `@readonly` instead
- `@const` - Use `@readonly` for constants
